# MCP-сервер для агентов деканата (BRIEF v2 §7)

MCP-сервер поверх **stdio**: агент сотрудника деканата (или внешний
MCP-клиент) подключается к тем же данным кабинета, что и веб-приложение,
и получает инструменты очереди заявок, объявлений, расписания,
статусов «болею», справочника преподавателей и успеваемости студента.

Сервер написан **без внешних SDK**: JSON-RPC 2.0 поверх newline-delimited
JSON реализован в `src/protocol.ts`. Новых зависимостей у пакета нет,
кроме тех, что уже есть в монорепе (`@udgu/core`, `zod`, `tsx`,
`typescript`).

> **Данные синтетические.** Как и весь прототип «Цифровой деканат
> будущего», сервер работает с вымышленными студентами, оценками,
> заявками и расписанием УдГУ. Никаких реальных персональных данных и
> никаких подключений к реальным системам вуза. Это учебный концепт,
> не официальный сервис УдГУ.

## Как устроена авторизация

Новой модели пользователей и токенов в схеме намеренно **нет**. Сервер
принимает **существующий токен сессии кабинета** — тот самый, который
браузер получает при входе `staff1`/`admin1` (httpOnly-cookie
`udgu_session`), — и проверяет его боевым `validateSession` из
`packages/core`.

- Токен приходит из переменной окружения `MCP_SESSION_TOKEN` **или**
  первым параметром `initialize` (`params.sessionToken`); явный параметр
  клиента имеет приоритет.
- Токен **никогда не логируется**: ни в stdout (это канал протокола), ни
  в stderr, ни в тексте ошибки. В диагностиках — только факт наличия.
  Токен сессии равносилен паролю.
- Сессия проверяется **на каждом вызове инструмента**: отзыв сессии
  (выход из кабинета) отключает агента сразу, а не до перезапуска.
- Прав у сервера нет своих: каждый инструмент вызывает сервис кабинета
  (`packages/core`), а тот сам проверяет роль и область видимости
  (`requireStaffScope`): сотрудник видит только свой институт,
  администратор — все.

## Как получить токен сессии

Поднимите кабинет (`npm run dev`), затем войдите сотрудником деканата:

```bash
curl -sS -D - -o /dev/null -X POST http://localhost:3000/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"login":"staff1","password":"aJMSwSxV_859b7A5"}' | grep -i 'set-cookie'
```

Значение cookie `udgu_session=…` — и есть токен сессии. Пароль тестовых
аккаунтов опубликован в корневом `README.md` (демо-пароль публичный by
design, в продакшне пароли задаются только через окружение).

## Как запустить

```bash
# из корня репозитория
MCP_SESSION_TOKEN=<значение cookie udgu_session> npm run mcp:serve

# или из packages/mcp
MCP_SESSION_TOKEN=<токен> npm run mcp:serve
```

Сервер говорит по stdio: пишет JSON-RPC в stdout, диагностику — в stderr.
Конец stdin завершает процесс. Для агента это обычный MCP-транспорт:
`initialize` → `tools/list` → `tools/call`.

Пример клиента (поднимает сервер дочерним процессом и проходит весь путь):

```bash
MCP_SESSION_TOKEN=<токен> node packages/mcp/examples/agent-client.mjs
```

## Инструменты

Все имена с префиксом `deanery_`. Аргументы валидируются zod-схемой;
некорректные аргументы — отказ `-32602 INVALID_PARAMS` с человеческим
текстом.

| Инструмент | Аргументы | Что делает | Сервис ядра |
| --- | --- | --- | --- |
| `deanery_requests_list` | `status?` | Очередь заявок и справок института | `listStaffRequests` |
| `deanery_request_decide` | `requestId`, `status`, `staffComment?` | Решение по заявке (в работе / готова / отклонена; для отказа нужен комментарий) | `decideStaffRequest` |
| `deanery_announcements_list` | — | Объявления: общие, института, групп института | `listStaffAnnouncements` |
| `deanery_announcement_publish` | `title`, `body`, `audience?`, `groupId?`, `faculty?`, `pinned?` | Публикация объявления + уведомление студентам аудитории | `createStaffAnnouncement` |
| `deanery_sick_leaves` | `activeOnly?`, `from?`, `to?` | Кто из студентов болеет (факт наличия справки, без файлов) | `listStaffSickLeaves` |
| `deanery_schedule` | `groupName?`, `from?`, `to?` | Пары групп института за период (по умолчанию две недели) | `listStaffSchedule` |
| `deanery_lesson_move` | `lessonId`, `date`, `room?`, `note?` | Перенос пары + уведомление группе | `moveStaffLesson` |
| `deanery_lesson_cancel` | `lessonId`, `reason` | Отмена пары с причиной | `cancelStaffLesson` |
| `deanery_teachers_list` | — | Справочник преподавателей | `listTeachers` |
| `deanery_teacher_card` | `teacherId`, `dateFrom?`, `dateTo?` | Расписание преподавателя и часы приёма | `getTeacherCard` |
| `deanery_student_grades` | `login` | Успеваемость студента: семестры, оценки, средний балл, долги | `listStudentGradesForStaff` |

Ответ инструмента — те же данные, что видит сотрудник в кабинете
(`structuredContent` + тот же JSON текстом). Внутренние поля наружу не
отдаются: путей из приватного хранилища (`storagePath`), путей к фото
справок, хешей паролей и токенов в ответах нет — это проверяется тестом.

## Демо-сценарий для агента деканата

1. `initialize` с токеном сотрудника → рукопожатие, сервер сообщает,
   какие инструменты есть.
2. `tools/list` → агент читает описания и схемы (11 инструментов).
3. `deanery_requests_list` → «что в очереди моего института».
4. `deanery_student_grades` с логином `student1` → «как успеваемость у
   автора заявки»: средний балл, долги, что подтянуть.
5. `deanery_request_decide` → «взять в работу» или «отклонить» с
   причиной; студент получает уведомление на сайт и в свой канал.
6. `deanery_announcement_publish` → объявление институту; видно в
   `deanery_announcements_list`.
7. `deanery_schedule` / `deanery_lesson_move` → перенести пару и
   уведомить группу.

Тот же сценарий целиком проходит в тесте
`test/protocol.test.ts` на живом дочернем процессе сервера.

## Отказы (JSON-RPC error)

| Код | Когда |
| --- | --- |
| `-32001` | Токен сессии не передан (ни env, ни `initialize`) |
| `-32002` | Токен передан, но сессия недействительна или истекла |
| `-32003` | Недостаточно прав: студент, преподаватель без факультета, чужой институт (`NOT_OWNER`, `STAFF_ONLY`) |
| `-32004` | Конфликт бизнес-правила (заявка закрыта, пара отменена) |
| `-32005` | Сущность не найдена в вашем институте |
| `-32006` | Инструмента с таким именем нет |
| `-32602` | Некорректные аргументы инструмента |

В `data` ошибки кладётся машинный код ядра (`NOT_OWNER`, `INVALID_INPUT`,
…) и уточнения по полям — чтобы агент-программа мог реагировать точно, а
человек читал понятный текст.

## Скрипты и тесты

```bash
npm run mcp:serve   # поднять сервер на stdio (нужен MCP_SESSION_TOKEN)
npm run typecheck   # tsc --noEmit
npm run build       # tsc → dist (артефакт; рантайм-вход — src/serve.ts через tsx)
npm test            # протокол на живом stdio: авторизация, права, инструменты
```

Тесты используют изолированную тестовую базу (`packages/db`
`ensureTestDatabase`) и вымышленные фикстуры; прод-база не трогается.
