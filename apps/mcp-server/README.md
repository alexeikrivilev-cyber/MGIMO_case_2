# MCP-сервер для агентов деканата (BRIEF v2 §7)

MCP-сервер поверх **официального MCP SDK** (`@modelcontextprotocol/sdk`):
агент сотрудника деканата (или внешний MCP-клиент — Claude, Cursor, свой
скрипт) подключается к тем же данным кабинета, что и веб-приложение, и
получает инструменты очереди заявок, объявлений, расписания, статусов
«болею», справочника преподавателей и успеваемости студента.

Два транспорта на одном наборе инструментов:

- **stdio** — агент поднимает сервер дочерним процессом своей сессии;
- **HTTP** (Streamable HTTP, stateless) — сервер работает как сервис,
  клиент подключается по URL.

Единый пакет `@udgu/mcp-server` (инструменты + транспорты). Своих
запросов к БД у инструментов нет: каждый инструмент — тонкая обёртка над
сервисом `packages/core`, тем же, что вызывает веб-кабинет.

> **Данные синтетические.** Как и весь прототип «Цифровой деканат
> будущего», сервер работает с вымышленными студентами, оценками,
> заявками и расписанием УдГУ. Никаких реальных персональных данных и
> никаких подключений к реальным системам вуза. Это учебный концепт,
> не официальный сервис УдГУ.

## Как устроена авторизация

Новой модели пользователей и токенов в схеме намеренно **нет**. Сервер
принимает **существующий токен сессии кабинета** — тот самый, который
браузер получает при входе `staff1`/`admin1` (httpOnly-cookie
`udgu_session`), — и проверяет его боевым `validateSession` из
`packages/core`.

- Токен приходит из переменной окружения `MCP_SESSION_TOKEN` (stdio) или
  заголовка `Authorization: Bearer <токен>` (HTTP).
- Токен **никогда не логируется**: ни в stdout (это канал протокола), ни
  в stderr, ни в тексте ошибки. В диагностиках — только факт наличия.
  **Токен сессии равносилен паролю**: только env, никогда в код, compose
  и логи.
- Сессия проверяется **на каждом вызове инструмента**: отзыв сессии
  (выход из кабинета) отключает агента сразу, а не до перезапуска.
- Прав у сервера нет своих: единый шлюз — `requireStaffScope` ядра
  (STAFF/ADMIN, см. `src/server.ts`), дальше каждый инструмент вызывает
  сервис кабинета, а тот сам проверяет владение данными. **Что проверяет
  ядро:** сотрудник видит только свой институт, администратор — все;
  студент и преподаватель в кабинет деканата не попадают (fail-closed,
  отказ `STAFF_ONLY` на любом инструменте).

### Как получить токен сессии

Поднимите кабинет (`npm run dev`), затем войдите сотрудником деканата:

```bash
curl -sS -D - -o /dev/null -X POST http://localhost:3000/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"login":"staff1","password":"aJMSwSxV_859b7A5"}' | grep -i 'set-cookie'
```

Значение cookie `udgu_session=…` — и есть токен сессии. Демо-пароль
публичный by design (опубликован в корневом `README.md`); в продакшне
пароли задаются только через окружение.

## Как запустить

```bash
# из корня репозитория
MCP_SESSION_TOKEN=<значение cookie udgu_session> npm run mcp:serve

# HTTP (порт 8787, хост 127.0.0.1 — только локальный интерфейс)
MCP_SESSION_TOKEN=<токен> npm run mcp:serve:http
```

Порты и хост настраиваются: `MCP_HTTP_PORT`, `MCP_HTTP_HOST`; транспорт —
`MCP_TRANSPORT=stdio|http` или аргумент `--transport stdio|http`.
Проверка здоровья HTTP: `GET /healthz` → `{"ok":true}` без авторизации.

Корневой `.env` подхватывается автоматически, если `DATABASE_URL` не
задан в окружении (путь к `.env` — от расположения кода, не от рабочего
каталога): агент может запустить сервер из любого каталога.

Пример клиента на SDK (поднимает сервер дочерним процессом и проходит
весь путь, либо подключается по HTTP, если задан `MCP_HTTP_URL`):

```bash
MCP_SESSION_TOKEN=<токен> node apps/mcp-server/examples/deanery-agent.mjs
MCP_SESSION_TOKEN=<токен> MCP_HTTP_URL=http://127.0.0.1:8787/mcp \
  node apps/mcp-server/examples/deanery-agent.mjs
```

### Конфигурация для агента деканата

Сниппет `mcpServers` для клиента вроде Claude Desktop / Cursor (пути —
от корня репозитория):

```json
{
  "mcpServers": {
    "udgu-deanery": {
      "command": "node",
      "args": [
        "--import",
        "tsx",
        "apps/mcp-server/src/index.ts",
        "--transport",
        "stdio"
      ],
      "env": {
        "MCP_SESSION_TOKEN": "<значение cookie udgu_session>",
        "DATABASE_URL": "postgresql://postgres:postgres@localhost:5432/horizon?schema=public"
      }
    }
  }
}
```

Для HTTP-транспорта клиент настраивается URL-ом и заголовком
авторизации (`Authorization: Bearer <токен>`).

## Инструменты

Ответ инструмента: `content` — тот же JSON текстом, `structuredContent` —
структурированные данные (массивы кладутся в `items`: `structuredContent`
по спецификации MCP — объект). Отказ инструмента (нет прав, нарушено
бизнес-правило, сущность не найдена) возвращается как `result.isError` с
человеческим текстом — так рекомендует спецификация MCP, чтобы агент
видел ошибку и мог исправить вызов.

| Инструмент | Аргументы | Что возвращает | Сервис ядра |
| --- | --- | --- | --- |
| `list_requests` | `status?` | Очередь заявок и справок института | `listStaffRequests` |
| `decide_request` | `requestId`, `status`, `staffComment?` | Решение по заявке (в работе / готова / отклонена; для отказа нужен комментарий) | `decideStaffRequest` |
| `list_announcements` | — | Объявления: общие, института, групп института | `listStaffAnnouncements` |
| `publish_announcement` | `title`, `body`, `audience?`, `groupId?`, `faculty?`, `pinned?` | Публикация объявления + уведомление студентам аудитории | `createStaffAnnouncement` |
| `sick_statuses` | `activeOnly?`, `from?`, `to?` | Кто из студентов болеет (факт наличия справки, без файлов) | `listStaffSickLeaves` |
| `get_schedule` | `groupName?`, `from?`, `to?` | Пары групп института за период (по умолчанию две недели) | `listStaffSchedule` |
| `move_lesson` | `lessonId`, `date`, `room?`, `note?` | Перенос пары + уведомление группе | `moveStaffLesson` |
| `cancel_lesson` | `lessonId`, `reason` | Отмена пары с причиной | `cancelStaffLesson` |
| `list_teachers` | — | Справочник преподавателей | `listTeachers` |
| `get_teacher_card` | `teacherId`, `dateFrom?`, `dateTo?` | Расписание преподавателя и часы приёма | `getTeacherCard` |
| `get_grades` | `login` | Успеваемость студента: семестры, оценки, средний балл, долги | `listStudentGradesForStaff` |

Внутренние поля наружу не отдаются: путей из приватного хранилища
(`storagePath`), путей к фото справок, хешей паролей и токенов в ответах
нет — это проверяется тестом.

### Демо-сценарий для агента деканата

1. `initialize` с токеном сотрудника → рукопожатие, сервер сообщает,
   какие инструменты есть.
2. `tools/list` → агент читает описания и схемы (11 инструментов).
3. `list_requests` → «что в очереди моего института».
4. `get_grades` с логином `student1` → «как успеваемость у автора
   заявки»: средний балл, долги, что подтянуть.
5. `decide_request` → «взять в работу» или «отклонить» с причиной;
   студент получает уведомление на сайт и в свой канал.
6. `publish_announcement` → объявление институту; видно в
   `list_announcements`.
7. `get_schedule` / `move_lesson` → перенести пару и уведомить группу.

Тот же сценарий целиком проходит в тестах `test/mcp-sdk.test.ts`
(in-memory транспорт SDK), `test/stdio.test.ts` (живой дочерний процесс)
и `test/http.test.ts` (живой HTTP).

## Скрипты и тесты

```bash
npm run mcp:serve        # поднять сервер на stdio (нужен MCP_SESSION_TOKEN)
npm run mcp:serve:http   # поднять сервер на HTTP (127.0.0.1:8787)
npm run typecheck        # tsc --noEmit
npm run build            # tsc → dist (артефакт; рантайм-вход — src/index.ts через tsx)
npm test                 # SDK in-memory + живой stdio + живой HTTP
```

`npm start` запускает собранный артефакт (`node --import tsx dist/index.js`):
воркспейсы монорепо (`@udgu/core`) поставляются TypeScript-исходниками,
поэтому загрузчик tsx нужен и для dist — он резолвит импорты ядра.

Тесты используют изолированную тестовую базу (`packages/db`
`ensureTestDatabase`) и вымышленные фикстуры; прод-база не трогается.
