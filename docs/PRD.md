# PRD — «Цифровой деканат будущего» (proj-3311)

> Автор: Hermes (тимлид, продуктовая аналитика). Утверждает: PO (proj-3311).
> Источник истины по требованиям: `docs/CASE.md`. Бриф заказчика: `docs/BRIEF.md`.
> Статус: v1.0 — принято в работу (P1).

## 1. Проблема и для кого

**Кто:** студент Университета «Горизонт» (вымышленный вуз), 18–22 года, живёт с телефона.

**Что болит:** учебная жизнь разбросана — расписание на сайте вуза, оценки в одной системе,
справки через очередь в деканате, объявления в чатах и на почте. С телефона каждое из этих
мест неудобно, а вместе — невыносимо: чтобы ответить на вопрос «что у меня завтра и всё ли
со мной в порядке», студент тратит 4–5 переходов между системами.

**Задача продукта (JTBD):** «Когда я открываю кабинет с телефона, я хочу за 10 секунд понять,
что у меня сегодня по учёбе и всё ли со мной в порядке, чтобы не бегать по сайтам и чатам и
не стоять в очереди в деканате.»

Вторичные JTBD: «подать справку, не идя в деканат»; «увидеть, что пару перенесли/отменили»;
«понять, что подтянуть перед сессией».

## 2. Цели и метрики успеха

| Цель | Как измеряем (на прототипе) |
|---|---|
| Ядро проходит end-to-end | Сценарии из §5 проходятся без ошибок в браузере |
| Скорость на телефоне | LCP < 2.5 с на 360 px, переходы между разделами мгновенные |
| Безопасность | 100 % роутов данных фильтруются по `session.studentId`; IDOR-тесты зелёные |
| Понятность | Новый пользователь находит расписание/оценки/заявку без подсказок |

## 3. Объём (Scope)

### 3.1. В рамках P1 (обязательное ядро)

| # | Фича | Ключевые требования |
|---|---|---|
| F1 | Вход по логину/паролю | argon2id, httpOnly-cookie сессия, rate-limit 5/15 мин на логин+IP, общие сообщения об ошибках, CSRF-защита мутаций |

## 4. Архитектура решения (выбор Hermes в рамках ориентиров PO)

**Рамка принятия:** `thinking-reversibility` — решения, которые дорого откатывать, принимаем
максимально консервативно; обратимые — быстро.

| Решение | Выбор | Почему | Обратимость |
|---|---|---|---|
| Монорепо | npm workspaces | Одна кодовая база UI+API+домен, общие типы | Высокая |
| Frontend + BFF | Next.js 15, App Router, TypeScript | Ориентир PO; SSR + Route Handlers в одном месте | Средняя |
| Стили | Tailwind CSS 4 + токены в `packages/ui` | Быстро, консистентно, мобильный-first | Высокая |
| БД | PostgreSQL 16 + Prisma 7 | Ориентир PO; реляционная модель, миграции | Средняя |
| Auth | Своя: argon2id + httpOnly-cookie + сессия в БД | Полный контроль безопасности (требование кейса) | Средняя |
| Домен | `packages/core` — чистые функции + сервисы | Тестируемость без БД, переиспользование MCP-сервером | Высокая |
| Валидация | zod на границе API | Требование ARCHITECTURE §4 | Высокая |

**Правило владения данными (ключевое):** любой доступ к данным студента идёт через серверный
сервис, который принимает `session.userId` и сам резолвит `studentId`. Идентификаторы в URL
никогда не являются источником истины о том, чьи это данные — они проверяются на владение.

## 5. Сценарии приёмки (проходим в браузере перед сдачей P1)

1. **Вход:** `/login` → неверный пароль даёт общую ошибку и не раскрывает существование логина;
   верный пароль → редирект в кабинет, cookie httpOnly.
2. **Расписание:** сегодня — видно текущую/следующую пару; неделя — 7 дней; перенесённая пара
   имеет бейдж «перенесена» с новой аудиторией; отменённая — зачёркнута/серая с причиной.
3. **Успеваемость:** список дисциплин с оценками/зачётами по семестрам + сводка (GPA, долги, тренд).
4. **Заявка:** подать справку → появилась в списке со статусом «Новая» → в истории видна.
5. **Уведомления:** непрочитанные видны, отмечаются прочитанными.
6. **IDOR:** student2 не видит оценки/заявки/расписание student1 (проверяем подстановкой ID).
7. **Мобильный:** все сценарии на 360 px без горизонтального скролла.
8. **Концепт:** баннер виден на всех экранах кабинета.

## 6. Нефункциональные требования

- Мобильный 360 px — first-class, не «адаптация».
- Только вымышленные данные; никаких реальных ФИО/оценок/зачёток.
- Секреты только в env; в браузере — только httpOnly-cookie сессии.
- Доступность: WCAG 2.2 AA (контраст, фокус, размер целей ≥ 44 px, семантика).
- Запрет заглушек в продакшн-путях: каждая фича имеет реальную реализацию и тест.

## 7. Риски и что делаем

| Риск | Митигиция |

## 8. Что осознанно НЕ делаем в P1

Реальные интеграции с системами вуза, восстановление пароля по почте (нет реального SMTP —
делаем демо-поток с пометкой), кабинет сотрудника, AI-ассистент, MCP-сервер, PWA-оффлайн.
