Wave 4. Что это

Волны 1–3 оживиния отклик, данные и «где я». Остался главный экран диалога — чат ассистента. Он работает, но ведёт себя как форум, а не как разговор: помнит только последний обмен, не отзывается на отправку и не показывает, на каких данных построен ответ. Волна 4 — лента обменов, немедленный пузырь студента, индикатор «печатает» и ссылки-источники в ответе.

1. Лента диалога вместо последнего обмена

Состояние панели: массив обменов { question, answer, mode, sources, error? }[]. Новый вопрос ДОБАВЛЯЕТ обмен (пузырь студента появляется сразу, синхронно, до сети), ответ заполняет его по id. Follow-up чипы и стартовые подсказки остаются только у последнего обмена — иначе они дублировались бы под каждым ответом (BRIEF v4: одна мысль на экран).

Источники:Успеваемость
  • Пузырь студента — справа, bg-primary-soft + рамка primary; ассистента — слева, bg-surface + рамка border. Ни одного нового цвета: токены волны 1.
  • max-width: 85%, overflow-wrap: anywhere, white-space: pre-line — длинный план с окнами переносится, 360 px держит (проверяется живьём).
  • Живая область aria-live="polite" — ТОЛЬКО на последнем пузыре ответа. История не анонсируется: иначе скринридер перечитывал бы весь диалог на каждый ответ.

2. Отклик на отправку: пузыръ сразу, «печатает» в ленте

Отправка вопроса: пузыръ студента появляется в ленте синхронно (setState до fetch) — отдача на действие без ожидания сети. На месте будущего ответа — пузыръ ассистента с индикатором «печатает» (три точки, пульсация 1s, задержка 150ms на точку) и sr-only «Ассистент печатает…». Карточка-спиннер «Думаем…» УБИРАЕТСЯ (via-negativa): её смысл полностью несёт индикатор в ленте, а два индикатора на один ответ — шум.

Есть новые уведомления?
Ассистент печатает…
  • Печать ответа посимвольно НЕ делаем: ответ приходит целиком — посимвольный reveal был бы иллюзией генерации. Индикатор показывает РЕАЛЬНОЕ ожидание, не враёт.
  • Точки — @keyframes udgu-typing в globals.css под prefers-reduced-motion: no-preference (единый стиль волн: .bar, .nav-indicator). Под reduce — три статичные точки, глобальный reduce-блок их гасит.
  • Кнопка «Спросить» сохраняет loading + aria-busy — отклик есть на обоих уровнях.

3. Атрибуция: из каких данных собран ответ

Движок возвращает sources: { label, href }[] по интенту (единый маппинг в assistantClient.ts — лист-модуль без Prisma, общий для ядра и браузера):

  • DEBTS / STUDY_PLAN / AVERAGE / IMPROVE → Успеваемость /grades + Расписание /schedule (план закрытия использует свободные окна);
  • SCHEDULE_TODAY / SCHEDULE_NEXT → Расписание /schedule;
  • REQUESTS → Заявки /requests; NOTIFICATIONS → Уведомления /notifications;
  • HELP / UNKNOWN и заглушка гейта → источников НЕТ (ответ не построен на данных кабинета — врать нечем).
  • Ссылки-чипы под ответом: TEXT_LINK_SM_CLASS-стиль (dotted underline) в <a> — Hit ≥ 24px (WCAG 2.5.8), PRESS_FEEDBACK, FOCUS_RING. Это и доверие («не выдумано»), и навигация в раздел.
  • LLM-путь наследует sources от детерминированного ответа: данные у них одни и те же.

4. Преподавательский чат — тот же класс, те же примитивы

TeacherAssistantPanel несёт ровно тот же дефект (последний обмен, карточка-спиннер). Общие примитивы выносим в components/chat.tsx (ChatBubble, TypingIndicator, SourceLinks) и применяем в обеих панелях — иначе следующий экран снова расходился бы. Цитаты-разделы плана остаются ВНУТРИ пузыръ ассистента (там они уже есть и уже аттрибуция).

5. Границы волны (что НЕ делаем)

  • Ноль новых зависимостей, ноль новых цветов, ноль новых размеров.
  • Никаких аватаров-картинок, звуков, автоскролла-скриптов (скролл к новому обмену — нативное поведение фокуса/живой области, не вешаем скрипт).
  • Посимвольная печать, «ИИ думает…» с задержкой — фейк, не делаем.
  • Пустые состояния «с характером через иконку» — следующая волна, сюда не тащим.
