# Архитектура — ориентиры PO (детальные решения принимает Hermes)

Конкурсный прототип личного кабинета студента. Дедлайн кейса: **28 ноября 2026**; внутренний дедлайн PO: **21 ноября 2026**.
Кейс: `docs/CASE.md` (источник истины). Бриф заказчика: `docs/BRIEF.md`. Этот документ — технические ориентиры и ограничения; декомпозиция и детальные решения — за Hermes.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Frontend + BFF | **Next.js 15 (App Router, TypeScript)** | Одна кодовая база для UI и API, мобильный веб из коробки, легко масштабировать (stateless, Docker) |
| Стили | **Tailwind CSS 4** + токены дизайн-системы (`packages/ui/tokens`) | Быстрая разработка, консистентность, мобильный-first |
| БД | **PostgreSQL 16** через **Prisma ORM** | Реляционная модель (студент→группа→расписание→оценки), миграции, горизонтальный рост |
| Auth | Своя сессионная система: argon2id-хеш пароля, httpOnly cookie, CSRF, rate-limit | Полный контроль безопасности, ничего лишнего в браузере |
| AI-ассистент кабинета | Серверный сервис с **опциональным LLM** (ключ только в env) + детерминированный fallback | Работает без ключа; ключ никогда не попадает в код/браузер |
| MCP-сервер для деканата | Отдельный Node-сервис (MCP SDK, stdio + HTTP транспорт) | Агенты деканата работают с расписанием/оценками/заявками через стандартный протокол |
| Деплой | Docker Compose на Helsinki VPS (177.3.196.28, белый IP) | Открывается из России без VPN; работает до 28 ноября |

Вуз прототипа: **Удмуртский государственный университет (УдГУ)**, Ижевск (BRIEF v2). Название и структура вуза используются по кейсу, НО все данные — синтетические (сидер), логотип УдГУ не используется, реальные системы вуза не подключаются.

## 3. Модель данных (ядро)

- `User` — логин, argon2id-хеш, роль (`STUDENT` | `STAFF` | `ADMIN`)
- `Student` — ФИО, факультет, направление, курс, группа, email, номер зачётки (вымышленный)
- `Teacher` — ФИО, кафедра, должность
- `Subject` — название, код
- `Group` — название, факультет, курс, направление
- `ScheduleEntry` — группа, предмет, преподаватель, дата/время, аудитория, тип (лекция/семинар/лаба), статус (`SCHEDULED` | `MOVED` | `CANCELLED`), примечание
- `Grade` — студент, предмет, значение (2–5 / зачёт), тип (экзамен/зачёт/курсовая), дата, семестр
- `Request` — студент, тип (справка/заявление), данные формы, статус (`NEW` | `IN_PROGRESS` | `READY` | `REJECTED`), комментарий сотрудника
- `Announcement` — заголовок, текст, аудитория (все / факультет / группа), закрепление, автор
- `Notification` — пользователь, тип, заголовок, тело, прочитано, ссылка
- `Session` — пользователь, хеш токена, срок жизни
- `AuditEvent` — кто/что/когда (для безопасности и кабинета сотрудника)

Расширения под BRIEF v2 (верификация, регистрация, «болею», расписание преподавателей):
- `IdentityRegistry` — синтетический реестр студбилетов для мок-сверки
- `StudentVerification` — заявка на верификацию: путь к фото в приватном хранилище, распознанные данные, балл сверки, решение сотрудника
- `OAuthAccount` + `OAuthIntent` — привязка к VK ID / MAX / Telegram и эмуляция согласия
- `SickLeave` — период заболевания (виден преподавателям и деканату)
- `OfficeHour` — консультации и часы приёма преподавателя

Правило владения: **любой** запрос к данным студента фильтруется по `session.studentId` на сервере; подмена ID в URL не даёт чужих данных (проверка на каждый роут + тесты IDOR).

## 4. Безопасность (требования кейса)

- Студент видит только свои данные; сотрудник деканата — свой факультет; админ — всё.
- Пароли: argon2id, соль, параметры по умолчанию OWASP. Никогда не в открытом виде.
- Секреты (DB, LLM-ключ) — только env на сервере; в браузере — httpOnly cookie сессии.
- Rate-limit на вход (5 попыток / 15 мин на логин+IP), общие сообщения об ошибках.
- Заголовки безопасности: CSP, HSTS, X-Frame-Options, Referrer-Policy.
- Валидация всех входных данных (zod) на границе API.

## 5. Функциональность

**Ядро (обязательно):**
1. Вход по логину/паролю + профиль студента
2. Расписание: сегодня / неделя, аудитория, преподаватель, переносы и отмены
3. Успеваемость: оценки, зачёты, семестры, сводка «как у меня дела» (GPA, долги, тренд)
4. Заявки и справки: форма → статус → история; сотрудник обрабатывает
5. Уведомления: объявления деканата, дедлайны, изменения расписания

**Сверх ядра (гипотезы, после основы):**
6. AI-ассистент в кабинете (вопросы о своей учёбе, дедлайны, что подтянуть)
7. **MCP-сервер для агентов деканата** (расписание, оценки, заявки, объявления)
8. Кабинет сотрудника деканата: обработка заявок, публикация объявлений, переносы пар
9. PWA: установка на телефон, оффлайн-оболочка
10. Тема оформления, тёмная тема, пустые состояния, a11y (WCAG AA)
