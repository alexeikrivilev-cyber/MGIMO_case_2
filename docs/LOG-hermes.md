### Этап 4a (завершён). P1.4a «Серверный слой» — живой прогон и правка OAuth (параллельная сессия)

> Исполнитель — параллельная сессия Hermes (интерактивная main-сессия владельца,
> поднятая heartbeat-задачей; процесс-владелец LSP/воркеров — PID 8151). Раздел
> сохранён её авторством: это её отчёт о её ветке и её находках.

- Ветка `feat/api-auth`, исполнитель — OpenCode. Смерж в `master` через `--no-ff`
  (`2ffe290`), запушен.
- **QA-гейт Hermes — не только юнит-тесты, но и живой прогон HTTP на прод-сборке**
  (`npm run build` + `npm run start`), потому что 52 юнит-теста воркера пропустили
  два дефекта, видимых только в живом HTTP:
  1. **OAuth-callback требовал `login`**, хотя BRIEF v2 делает обязательными только ФИО
     и группу. Регистрация через провайдера без логина падала с 400 `INVALID_INPUT`.
     Исправлено: логин необязателен, при отсутствии выводится из аккаунта провайдера.
     Добавлен регрессионный тест «callback: логин НЕ обязателен» (две независимые
     регистрации без логина → обе 200).
  2. **`GET /api/auth/csrf` отдавал 500 в dev.** Причина — не код маршрута (он работает
     в изоляции), а устаревший `.next`: прод-сборка перезаписала dev-каталог, dev-сервер
     отдавал `Cannot find module './846.js'`. В прод-пуке роут отдаёт 200. Вывод для
     процесса: **окончательная проверка всегда на прод-сборке**, dev-артефакты `.next`
     не являются доказательством.
- **Живой прогон на прод-сборке (реальный вывод curl):**
  - `POST /api/auth/login` (student1/password123) → 200 + Set-Cookie;
  - неверный пароль и несуществующий логин → **одинаковый** 401 «Неверный логин или
    пароль» (нет перебора пользователей);
  - `GET /api/requests/<id заявки student1>` с сессией student2 → **404** (не 403 —
    не раскрывает существование);
  - `/staff` и `/admin` с сессией студента → **404**;
  - `/api/grades` для неверифицированного student2 → 403 `VERIFICATION_REQUIRED`;
    для student1 → 200, 16 записей, 2 семестра, сводка avg 3.8 / 1 долг / тренд UP;
  - POST без CSRF-токена → 403; с токеном → заявка и отметка «болею» создаются;
  - валидация периода болезни (dateFrom > dateTo) → 400 с понятным текстом;
  - OAuth: неизвестный провайдер → 404; полный поток start→callback без логина → 200.
- **Итог:** `npm test` → **201/201** (22 db + 126 core + 53 web), `npm run build` зелёно,
  typecheck в 4 воркспейсах зелёный, секретов нет.
- **Принятые воркером решения (для аудита):** CSRF-cookie выдаётся публично (иначе
  клиент не получит токен до входа); занятый логин в OAuth-callback → 409, а не

## 2026-11-20 — директива владельца: «оживить интерфейс» (P5, волны)

### Директива и ограничения (PO, 20.11 20:40)

Функционал работает, но интерфейс «мертвый»: не хватает визуализации,
интерактива, отдачи, анимаций. ЖЁСТКОЕ ограничение: НЕ наваливать кучу
визуала — минимум шума, но грамотно. Петля работы: Open Design делает
визуал/интерактив → Hermes КРИТИКУЕТ (не rubber-stamp) → OpenCode
исправляет → QA-гейт → мёрж --no-ff → push. Несколько волн. UI —
приоритет; при исчерпании отдачи волн — Improve-задачи (качество ответов
ИИ-ассистентов, сценарии ботов, edge cases).

### Аудит текущего UI (что именно «мертво», проверено чтением кода)

1. Успеваемость: тренд — только текст («на 0,08 выше прошлого семестра»),
   хотя `summarizeGrades` уже считает средние по семестрам — нет графика.
2. Расписание: список пар без привязки ко времени; неделя — стопка карточек
   дней; нет таймлайна дня.
3. Motion: нулевой. `transition-colors` на кнопках, `animate-pulse` на
   скелетонах — и всё. Нет отклика на нажатие, нет stagger, нет переходов.
4. Интерактив: ползунок «левериджа» — единственный живой виджет; формы
   после отправки делают полную перезагрузку страницы.
5. Заявки: статус — два бейджа, нет таймлайна «где моя заявка».
6. Ассистент: чат есть (AssistantPanel), UX не аудирован в этой волне.

### Рамки решений (как требовала директива)

- **thinking-via-negativa** («что убрать»): интерфейс мёртвый не от
  нехватки декора, а от отсутствия отклика и визуализации данных, которые
  УЖЕ есть. Значит: убрать текстовую сводку тренда → заменить графиком;
  убрать «мёртвый» список пар → таймлайн; убрать отсутствие отклика →
  press/stagger/переходы. Намеренно НЕ добавляем (через труп): parallax,
  анимированные градиенты, конфетти, chart-библиотеки (recharts и т.п.),
  framer-motion — вес и шум без информации.
- **thinking-pre-mortem** («чем опасно перекрасить»): (1) поломка 473/473
  тестов и SSR (страницы — серверные компоненты, новые интерактивные
  островки должны быть минимальны); (2) регресс 360 px (горизонтальный
  скролл — критерий приёмки); (3) WCAG: движение без
  prefers-reduced-motion — триггер HIGH по better-interface; (4) рост
  бандла/зависимостей. Контрмеры: НОЛЬ новых зависимостей (SVG и CSS
  рисуем руками, анимации — Tailwind motion-safe + @media reduce),
  серверный рендер графиков, тесты на новое поведение, живые проверки на
  next start :3100 и на проде.

1. **Часовой пояс: рельс противоречил дашборду (корректность).**
   `DayTimeline` читал «сейчас» локальными `getHours()/getMinutes()`, а
   весь конвейер расписания привязан к UTC: `startOfUtcDay`
   (services/schedule.ts:59), `toOccurrence` собирает мгновение пары
   через `Date.UTC` (там же:285–289), `getMyNextLesson` сравнивает
   абсолютные мгновения (там же:275), сидер `startOfDay` → `Date.UTC`
   (seed-data.ts:732). На хосте UTC (прод-контейнер) Local и UTC
   совпадают, поэтому на проде дефект невидим — но код зависел от TZ
   хоста. Воспроизведено на этом хосте (Europe/Samara, UTC+4) в 00:09
   локального 21.11 = 20:09 UTC 20.11: `/dashboard` «Ближайшая пара» →
   «23 ноября, 08:30–09:50» (пары сегодня закончились — правда), а рельс
   `/schedule` ставил маркер «Сейчас» ПЕРЕД первой парой 08:30 основным
   чипом — день «ещё не начался». Два экрана, противоречащие ответы.
   Исправление: `now.getUTCHours() * 60 + now.getUTCMinutes()`.
   **Второй порядок:** тесты рельса конструировали `now` локальным
   `new Date(2026, 0, 15, 13, 45)` — на не-UTC хосте после правки они бы
   упали. Переведены на `Date.UTC(...)`: тесты стали независимыми от TZ.
