# Чек-лист приёмки PO — proj-3311

Проверяю каждый приоритет (P1–P4) по этому списку. Отметка «ок» — только после личной проверки.

## P1 — Ядро

### Инфраструктура
- [ ] Репозиторий на GitHub (origin = MGIMO_case_2), README с инструкцией запуска
- [ ] `npm install` → миграции → сидер → `npm run build` проходят на чистом клоне
- [ ] Docker Compose поднимает БД; сидер создаёт синтетические данные УдГУ

### Вход и регистрация
- [ ] Вход по логину/паролю университетской УЗ (student1, student2, staff1, admin1)
- [ ] Неверный пароль → общая ошибка (без уточнения «нет такого логина»)
- [ ] Rate-limit на вход (5/15 мин → 429)
- [ ] Выход работает, cookie httpOnly
- [ ] Регистрация через VK ID / MAX / Telegram (эмуляция OAuth) с обязательными ФИО+группой
- [ ] Загрузка фото студбилета → мок-распознавание → сверка с синтетическим реестром
- [ ] До верификации: оценки и переписка НЕДОСТУПНЫ; после — доступны
- [ ] Фото студбилетов в приватном хранилище, без публичных ссылок

### Расписание
- [ ] «Сегодня» и «неделя», аудитория, преподаватель, тип занятия
- [ ] Переносы (MOVED) и отмены (CANCELLED) заметно оформлены
- [ ] Расписание преподавателей видно студенту (пары, консультации, часы приёма)

### Успеваемость (только после верификации)
- [ ] Оценки/зачёты по дисциплинам, фильтр по семестру
- [ ] Сводка «как у меня дела»: средний балл, долги, тренд
- [ ] Разные данные у student1 и student2

### Заявки и уведомления
- [ ] Создание заявки/справки, статусы, история
- [ ] Уведомления: лента, непрочитанные, счётчик

### Статус «болею»
- [ ] Студент отмечает болезнь (период, при желании — справка)
- [ ] Преподаватель/деканат видят статус (в прототипе — синтетический реестр)

### Безопасность (критично)
- [ ] student2 НЕ может открыть оценки/заявки/переписку student1 подстановкой ID (проверяю руками)
- [ ] /staff и /admin недоступны студенту (404)
- [ ] Пароли в БД — только argon2id-хеши
- [ ] Секретов нет в коде и в браузере ( DevTools → Application/Storage)
- [ ] Мобильный 360 px: все экраны корректны
- [ ] Баннер «учебный концепт, не официальный сервис» на виду

## P2 — Глубина
- [ ] Кабинет сотрудника: заявки, объявления, переносы пар, верификация студбилетов, статусы болезней
- [ ] Переписка студент↔преподаватель: преподаватель видит ФИО/группу автора
- [ ] AI-ассистент студента: помогает с долгами/учёбой (по его данным)
- [ ] AI-ассистент преподавателя: загрузка учебного плана → RAG-подсказки
- [ ] MCP-сервер: инструменты (расписание, оценки, заявки, объявления, болезни) + пример клиента

## P3 — Качество
- [ ] Цельный дизайн, свой знак (не логотип вуза), тёмная тема
- [ ] Пустые состояния, ошибки, скелетоны — везде
- [ ] WCAG AA (контраст, фокус, aria), PWA-установка

## P4 — Сдача
- [ ] Деплой на Helsinki VPS, HTTPS, открывается из РФ без VPN
- [ ] Тестовые аккаунты работают на проде
- [ ] Документ процесса: проблема, ИИ-инструменты, промпты, скриншоты, защита
- [ ] Видео ≤5 мин (по желанию)
- [ ] Финальный проход по чек-листу кейса (docs/CASE.md)

## Правило приёмки
Любой failing пункт — возврат Hermes на доработку с конкретикой (что проверял, что получил). P2/P3/P4 не начинаются, пока P1 не принят.
