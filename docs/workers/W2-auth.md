# W2 — Аутентификация и профиль

## Задача для воркера

Реализовать вход по логину/паролю и профиль студента в монорепо (docs/ARCHITECTURE.md — источник истины).

### Что сделать

1. **packages/core — домена auth** (`src/auth/`):
   - argon2id хеширование паролей (библиотека, работающая на Node 24 без нативных сборок — напр. @node-rs/argon2 или argon2; проверить, что собирается).
   - Создание сессии: opaque токен (32 байта crypto.randomBytes), в БД хранится ТОЛЬКО хеш токена (sha256), cookie httpOnly, SameSite=Lax, Secure в продакшене, срок 7 дней.
   - Валидация сессии по cookie, удаление (logout), продление.
   - CSRF: double-submit token для мутирующих запросов.
   - Rate-limit входа: 5 попыток / 15 мин на пару (логин, IP) — in-memory Map с очисткой, ответ 429 с Retry-After.
   - Ошибки входа не различают «нет такого логина» и «неверный пароль».

2. **apps/web — UI и API**:
   - `/login` — мобильная форма (логин, пароль, показать/скрыть пароль), состояния загрузки/ошибки, ссылка-заглушка «Забыли пароль?» (ведёт на заглушку с текстом-концептом).
   - `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/me`.
   - Middleware: защита всех роутов кабинета, редирект на /login; редирект с /login если уже авторизован.
   - Роли из сидера: student1/student2 (STUDENT), staff1 (STAFF, факультет ФИТ), admin1 (ADMIN). Проверить, что сидер создаёт этих пользователей; если нет — дополнить сидер (пароли password123, argon2id).
   - Профиль `/profile`: ФИО, факультет, направление, курс, группа, номер зачётки, email, телефон. Чтение из БД; контактные данные — редактирование (валидация zod, сохранение).
   - Layout кабинета: мобильная навигация (нижний таб-бар: Главная, Расписание, Оценки, Заявки, Профиль) + шапка с именем и выходом. Контент главной — приветствие и быстрые ссылки (заглушки до появления разделов).

3. **Проверка**: `npm run build` проходит; ручной сценарий: логин student1 → видит свой профиль; logout; неверный пароль → общая ошибка.

4. Коммит: `feat(auth): вход по паролю, сессии, профиль`.
