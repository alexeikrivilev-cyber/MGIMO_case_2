# W8 — AI-ассистент в кабинете

## Задача для воркера

Реализовать AI-ассистента студента (docs/ARCHITECTURE.md — истина). Принцип: сначала детерминированный движок (работает всегда), опциональный LLM как надстройка (ключ только из env на сервере).

### Что сделать

1. **packages/core/src/assistant/** — движок ответов по данным студента из сессии:
   - Интенты: «что у меня сегодня/завтра», «мои долги», «что подтянуть» (предметы с низкими оценками), «когда следующая пара», «средний балл», «мои заявки и их статусы», «дедлайны» (что готовится/ближайшие события), «кто преподаёт X», «где пара X» (аудитория), приветствие/помощь («что ты умеешь»).
   - Ответы — с конкретными данными студента, краткие, дружелюбные, без выдумывания фактов. Fallback: «Я пока отвечаю только про твою учёбу» + подсказки.
   - Формат ответа: текст + опциональные структурированные блоки (список пар, таблица оценок) — рендерятся в UI.

2. **apps/web**:
   - UI: плавающая кнопка/панель ассистента (мобильный — bottom-sheet, десктоп — боковая панель); список сообщений, индикатор «печатает», быстрые подсказки-вопросы.
   - API `POST /api/assistant/chat` — принимает сообщение, возвращает ответ движка.
   - Опциональный LLM: если `LLM_API_KEY` задан в env сервера — запрос к OpenAI-совместимому endpoint (`LLM_BASE_URL`, `LLM_MODEL`) с системным промптом и данными студента как контекст; при ошибке/отсутствии ключа — молча откат на детерминированный движок. Ключ НИКОГДА не отправляется в браузер.

3. Прозрачность: в ответах с LLM — пометка «ответ сгенерирован ИИ, проверяй важные данные».

4. Коммит: `feat(assistant): AI-ассистент кабинета`.
