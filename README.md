# Цифровой деканат будущего — личный кабинет студента УдГУ

**Рабочий прототип «цифрового деканата будущего» для Удмуртского государственного университета:** расписание, успеваемость, заявки и справки, уведомления, верификация по студбилету, статус «болею», AI-ассистенты студента и преподавателя, кабинет сотрудника деканата, MCP-сервер для агентов деканата и боты Telegram / VK / MAX — в одном месте, с телефона, с нуля вымышленными данными.

> **Это учебный концепт для конкурса, не официальный сервис УдГУ.** Все данные в системе синтетические (ФИО, оценки, зачётки, фото студбилетов — вымышленные), настоящих персональных данных нет, подключений к реальным системам вуза нет.

## Демо

**https://177-3-196-28.nip.io/** — прод-выкладка на Helsinki VPS (Docker, PostgreSQL 16, HTTPS с сертификатом Let's Encrypt). **Открывается из России без VPN.**

Вход — по тестовым аккаунтам из раздела [«Тестовые аккаунты»](#тестовые-аккаунты-вымышленные); на странице входа есть кнопки «Демо-доступ», которые подставляют логин и пароль.

## Почему это решение закрывает задачу организаторов

Кейс просит: рабочий прототип (не макет), всё в одном месте, удобно с телефона от 360 px, безопасно (студент видит только свои данные, пароли и ключи не в коде), только вымышленные данные, процесс создания с ИИ описан полно. Ниже — по каждому требованию кейса: что сделано и чем это подтверждается.

### 1. «Работающий прототип, а не макет» — пройдён полный пользовательский путь

Войти → увидеть расписание на сегодня и неделю → посмотреть оценки → подать заявку и увидеть её статус → прочитать уведомления. Всё это работает на проде по ссылке выше, без VPN, из России. Приёмочный прогон по чек-листу кейса — **25/25 проверок зелёные** (предыдущий — 55/55), состояние каждой проверки с датами — в [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md). Данные сохраняются: заявка, поданная в кабинете, видна сотруднику деканата; заявка из бота — видна на сайте (общий бэкенд, живые прогоны в логе этапов).

### 2. «Всё в одном месте» — ядро кейса плюс то, что организаторы просили как «смелые идеи»

| Требование кейса | Как реализовано |
| --- | --- |
| Вход и профиль | Логин/пароль университетской УЗ + регистрация через VK ID / MAX / Telegram (эмуляция OAuth) с обязательными ФИО и группой; профиль с факультетом, направлением, курсом, группой |
| Расписание | «Сегодня» и «неделя», аудитория, преподаватель, тип занятия; **переносы и отмены выделены цветом и текстом** (не только цветом — требование доступности); расписание преподавателей с часами приёма |
| Успеваемость | Оценки и зачёты по дисциплинам, фильтр по семестру, сводка «как у меня дела»: средний балл, долги, тренд (SVG-график) |
| Заявки и справки | Онлайн-заказ, статусы, таймлайн истории заявки |
| Уведомления | Лента, непрочитанные, счётчик, напоминания об изменениях пар |

**Сверх ядра** — то, что отличает работу от «ещё одного кабинета» и показывает, каким деканат может стать:

- **Верификация по студбилету с гейтом доступа.** До сверки документа оценки и переписка закрыты; фото студбилета идёт в приватное хранилище, сверка — с синтетическим реестром. Почему: в кейсе безопасность и «каждый видит только свои данные» — это не абстрактная галочка, а реальный пользовательский сценарий «новый студент в первом семестре».
- **Статус «болею».** Студент отмечает период болезни (по желанию — со справкой в приватное хранилище), преподаватель и деканат видят статус. Почему: одна из самых частых причин ходить в деканат физически.
- **AI-ассистент студента** (`/assistant`): долги, план их закрытия с опорой на расписание, «леверидж» — сколько баллов нужно на оставшихся работах до целевого среднего, заявки, уведомления. Детерминированный движок по данным владельца сессии; LLM опционален (ключ в env), без ключа — честный детерминированный режим. Почему: кейс просит, чтобы учёба была понятна студенту, а не просто «выводила цифры».
- **AI-ассистент преподавателя с RAG** (`/teacher/plans`, `/teacher/assistant`): преподаватель загружает учебный план (`.md`/`.txt`), детерминированный TF-IDF-индекс по чанкам (без облачных векторов и внешних зависимостей), ответы — с цитатами разделов плана и сопоставлением тем с долгами студентов его групп. Почему: показать ИИ внутри продукта, а не только в процессе разработки.
- **Кабинет сотрудника деканата** (`/staff`): очереди заявок и верификаций, статусы болезней, публикация объявлений, перенос и отмена пар. Почему: кейс прямо просит аккаунт сотрудника, «если есть кабинет сотрудника».
- **MCP-сервер для агентов деканата** (`apps/mcp-server`, официальный SDK): 11 инструментов (заявки, объявления, расписание, переносы, оценки, карточки преподавателей) на двух транспортах — stdio и HTTP. Авторизация — существующим токеном сессии кабинета, прав у сервера нет: он вызывает те же сервисы, поэтому сотрудник видит только свой институт. Почему: «цифровой деканат будущего» — это деканат, с которым общаются не только люди, но и агенты; это следующий шаг после веба, и он уже работает.
- **Боты Telegram / VK / MAX** (`/channels`): те же сценарии ядра, тот же бэкенд, привязка канала одноразовым кодом из кабинета; без токенов в env канал честно помечен «демо-режим». Почему: студент живёт в мессенджерах — деканат должен приходить туда, где он уже есть.
- **Переписка студент ↔ преподаватель** (`/messages`) с гейтом верификации: преподаватель видит ФИО и группу автора.

### 3. «С телефона» — mobile-first, а не «адаптив на бумаге»

Все основные сценарии проходятся на экране 360 px: нижняя навигация, карточные списки, формы. Проверено живьём и закреплено тестами: **360 px без горизонтального скролла** (все экраны), вёрстка без фиксированных ширин больше 360 px (сторож в тестах страниц). Тёмная тема по умолчанию, PWA-установка (свой манифест, service worker с оффлайн-оболочкой; API и персональные страницы в кеш не пишутся — намеренно).

### 4. «Безопасно» — проверяемо, а не на словах

- **Студент видит только свои данные.** Владение проверяется в сервисах ядра, анти-IDOR — на всех сущностях: подстановка чужого ID даёт тот же обобщённый 404, что и «не найдено» (не «403 — чужая заявка», из которого можно узнавать существование данных). Живые прогоны и тесты: `apps/web/test` + `packages/core/test`.
- **Пароли — только argon2id-хеши**, проверено тестом сидера (хеш настоящий, верифицируется argon2).
- **Секретов нет в коде и в браузере:** ключи только в env, в репозитории — закомментированные плейсхолдеры (`.env.example`); сторож-тест ищет секреты в исходниках; cookie сессии httpOnly (+ SameSite, Secure), токен сессии никогда не логируется.
- **Rate-limit:** вход — 5 попыток / 15 мин → 429; действия кабинета (заявки, объявления, верификация, «болею») — независимые bucket'ы с честным `Retry-After` (живой прогон: 30-я отправка → 429, `Retry-After: 59`).
- **Одинаковый отклик на неверный пароль и на несуществующий логин** (выравнивание тайминга фиктивным хешем) — из ответа нельзя узнать, какой логин существует.
- **Приватное хранилище файлов** (`storage/` вне webroot): фото студбилетов, справки, учебные планы. Прямых ссылок нет, отдача — только через авторизованный серверный роут владельцу и верификатору, `no-store`. Валидация типа и размера + защита от выхода за каталог — в `packages/core/src/storage.ts` с тестами.
- **Заголовки безопасности и CSRF** — в middleware; `/staff` и `/admin` для студента отдают 404.

### 5. «Только вымышленные данные» и «не официальный сервис»

Весь датасет синтетический и при этом реалистичный: институты УдГУ, реальные коды направлений подготовки, группы вида ПИ-24-1, 22 пользователя, 16 преподавателей, 443 пары расписания с переносами и отменами, 65 оценок. Баннер «учебный концепт, не официальный сервис» — на виду на страницах. Логотип вуза не использован: знак концепта — свой («страница-расписание с печатью „всё учтено“»), источник — `apps/web/public/icon.svg`.

### 6. «Доступность для жюри»

Прод работает из России без VPN и остаётся открытым до 28 ноября. Вход — по тестовым аккаунтам (два студента с разными данными + преподаватель + сотрудник деканата + администратор), кнопки «Демо-доступ» на странице входа. Исходный код — этот репозиторий. Документ процесса создания — [`docs/PROCESS.md`](docs/PROCESS.md) (проблема, все ИИ-инструменты и роль каждого, ключевые промпты по этапам, разбор ошибок ИИ, защита простыми словами, что делалось вручную). Скриншоты ключевых экранов — [`docs/screenshots/`](docs/screenshots/).

## Качество: как прорабатывалось решение

Это не «сгенерировало и показало». Работу вели **инженерным контуром с QA-гейтом на каждом этапе**: каждая порция работы шла через ветку `feat/*` → проверки → мерж `--no-ff` → деплой, и весь путь зафиксирован в [`docs/LOG-hermes.md`](docs/LOG-hermes.md) (18 этапов + 6 волн доработок) и [`docs/PROCESS.md`](docs/PROCESS.md).

**Что входит в QA-гейт каждого этапа:**

1. `npm run typecheck` — во всех 5 воркспейсах;
2. `npm test` — **583 автотеста** (`node:test`): домен и безопасность ядра, анти-IDOR, страницы кабинета (рендер из реальных данных), контраст всех пар «текст → поверхность» в светлой и тёмной темах, паритет дизайн-токенов, MCP-протокол, боты, инварианты сидера;
3. чистая прод-сборка (57+ путей) и `db:seed`;
4. **живые прогоны на `next start`** против реальной БД: сценарии кабинета, 429-е ответы, XSS-payload уходит текстом, 360 px без overflow, `prefers-reduced-motion`, Tab-навигация с кольцом фокуса 2 px;
5. финальный приёмочный прогон **на проде по публичному URL** — 25/25.

**Сторожа (guard-тесты), которые не дают качеству просесть тихо:** утечка секретов в исходниках, однородность отклика интерактивных элементов, иконка раздела в каждом пустом состоянии (29 сайтов), детерминизм сидера и его инварианты на любом стартовом дне. Когда дизайн-обновление откатило 10 guarded-поведений — тесты это поймали, и фичи были возвращены в новом дизайне, а не выключены проверки. **Тесты не ослаблялись ни разу: если проверка ловит регрессию — чинится продукт.**

**Ошибки и конфликты ИИ разбирались, а не замалчивались.** Яркие примеры из [`docs/PROCESS.md`](docs/PROCESS.md) §6: обобщённые сообщения об ошибках вместо утечки внутренностей (в тесте специально проверяется, что `postgres://user:pass@host` не утекает в отклик); выравнивание тайминга входа; date-зависимые инварианты сидера, которые падали по выходным — найдены красным прогоном и починены так, что держатся на любом стартовом дне (проверка на 60 днях подряд); синтаксический мусор от параллельных правок воркеров — ловился сборкой до мержа.

**Документы для агентов не менее важны, чем код:** кейс, архитектура, план, PRD, глоссарий и ADR живут в `docs/`, потому что по ним работают сами ИИ-агенты — «проработка и структура документов и файлов для самих ИИ-агентов» из критериев кейса.

## Технологии и запуск

**Стек:** Next.js 15 (App Router, TypeScript) · Tailwind CSS 4 · Prisma 7 + PostgreSQL 16 · argon2id + httpOnly-cookie сессии · `node:test` + tsx · Docker Compose · официальный MCP SDK. Монорепо на npm workspaces: `apps/web` (кабинет), `apps/mcp-server`, `packages/db` (схема, миграции, сидер), `packages/core` (домен, безопасность, приватное хранилище, боты каналов), `packages/ui` (дизайн-токены).

**Локальный запуск** (нужны Node.js 24+ и Docker):

```bash
cp .env.example .env
docker compose up -d db      # PostgreSQL 16 на localhost:5432
npm install
npm run db:migrate           # миграции
npm run db:seed              # вымышленные данные УдГУ
npm run dev                  # http://localhost:3000
```

Скрипты (`npm test`, `npm run typecheck`, `npm run build`, `npm start`, `npm run mcp:serve`, `db:*`) — в разделе [«Скрипты»](#скрипты) полного README ниже. Технические детали (PWA и знак, service worker, доступность, приватное хранилище, Docker) — ниже.

## PWA, знак концепта и доступность

**Знак концепта — свой, не логотип вуза** (требование кейса): «страница-расписание с печатью „всё учтено“» — контур страницы, строки пар и галочка контроля в фирменных токенах кабинета. Источник истины — `apps/web/public/icon.svg`; PNG (`192`, `512`, `maskable-512`, `apple-touch-icon-180`) генерируются скриптом `apps/web/scripts/generate-icons.py` (Python + Pillow, без сетевых ресурсов) и тоже лежат в репозитории.

**Манифест** — `apps/web/public/manifest.webmanifest`, рукописный: `name` «Цифровой деканат — УдГУ», `short_name` «Деканат УдГУ», `start_url` `/login`, `display: standalone`, цвета из тёмных токенов. В описании прямо сказано, что это учебный концепт.

**Service worker** — `apps/web/public/sw.js`, регистрируется только в production. Навигация — сначала сеть, без сети отдаёт закешированную оболочку `/login`; статика `_next/static` — cache-first с лимитом 60 записей; **API не кешируется никогда** (персональные данные), RSC-потоки и HTML страниц кабинета в кеш не пишутся.

**Доступность (WCAG 2.2 AA).** Skip-link «Перейти к содержимому» — первый фокус-элемент экранов входа и кабинета; видимый `focus-visible` у каждого интерактивного элемента; `aria-current="page"` на активном разделе; нижняя навигация — `<nav aria-label="Основная навигация">`; ошибки форм — `role="alert"` + `aria-describedby`; статусы кодируются формой **и** словом; `prefers-reduced-motion` гасит все анимации. Контраст закреплён тестами: `apps/web/test/contrast.test.ts` (все пары «текст → поверхность» ≥ 4.5:1 в светлой и тёмной темах) и `apps/web/test/tokens-parity.test.ts`.

## Docker

```bash
docker compose up -d          # db + web (web слушает порт 3000)
docker compose up -d db       # только база
```

Образ `web` собирается из `apps/web/Dockerfile` (Next.js standalone). Пароли только из переменных окружения (`.env`), в коде и compose их нет.

## Приватное хранилище файлов кабинета

Фото студенческих билетов (заявки на верификацию) — `storage/id-cards/<studentId>/<uuid>.<ext>`, учебные планы преподавателей — `storage/study-plans/<teacherId>/<uuid>.<md|txt>`, справки о болезни — там же. Хранилище в корне репозитория — **вне webroot**: Next.js отдаёт как статику только `public/`, поэтому прямых ссылок на файлы нет, доступ только через серверный код владельцу и верификатору. В базе хранится только путь относительно корня хранилища.

- Корень переопределяется переменной `STORAGE_DIR` (см. `.env.example`).
- Валидация и защита от выхода за пределы каталога — `packages/core/src/storage.ts` (фото: MIME только `image/jpeg` / `image/png` / `image/webp`, размер ≤ 5 МБ; планы: только `.md` / `.txt`, текст UTF-8, размер ≤ 1 МБ), тесты — `packages/core/test/storage.test.ts`.
